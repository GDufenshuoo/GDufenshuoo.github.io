MD Managers

​

Introduction ​

最近半年里终于接触到了需要管理大批量分子动力学模拟任务的需求。 在前期使用 LLM 辅助我写了一个半自动的模板，主要是辅助写了接口部分，是基于 Julia 的。 后来发现里面问题蛮多的，尤其是 LLM 实现的接口逻辑太臃肿了，于是在上个月左右重构了一遍。 这次使用的 LLM 工具是 Cursor 和 Gemini-CLI[1]。 总体思路是这样的：先详细描述需要完成怎样的工作流，然后看看 LLM 产生的框架怎么样。

然而就是这么一个简单的问题，LLM 也不能很好的完成。

Self-reflection！ ​

在遇到的所有问题当中，最突出的一个就是：LLM 会在最意想不到的地方出错！

诚然 LLM 确实编码非常快速，而且格式化做的非常好，该有的说明都有。但是，在问题的复杂度达到一定程度的时候，出错概率是几何倍上升的。比如写一个最简单的自相关中间散射函数的 Fortran 代码，你会发现其[2]会刻意避免最复杂的部分，尤其是解决不了出现的问题——往往是一些细节上的小问题，你一下就能发现的——如果你真的看了他生成的几百行代码的话，他会疯狂重构代码——大概率是删减逻辑，加一些跳过逻辑的代码，凑指标一样先跑通代码，然后交差......

叹息～该有的都不能少......一个人可以避免重复劳动，但是当他没有足够的技能完成这个工作，往往让别人（LLM）做的效果会非常差。

这里好像有些什么
于是痛定思痛！决心要手把手做一个自己的 Manager 用来管理整个模拟任务。

BLUEPOINT ​

需求 ​

对于玻璃化模拟来说，需要调整 压力 温度 粒子属性 以及一些奇奇怪怪的参数，来研究参数变换条件下的松弛时间与参数的关系，与某些物理量的关系，需要分析轨迹并归纳整理。

模拟流程 ​

每个模拟流程都有几个步骤：初始化 → 平衡到特定条件 → 采样 → 分析。
这些步骤需要严格按照实验设计进行，以确保结果的可靠性和可重复性。

抽象 ​

整个系统可以被抽象为三个部分：模拟-分析-汇总。

为了方便扩展体系，需要尽量精简代码结构，避免耦合、方便扩展、减少加入的组件数目，专注于获得数据，处理数据，归纳数据。
